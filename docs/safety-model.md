# Y-TEC Tsumugi Drive v2 安全モデル

更新日: 2026-08-04

対象: Y-TEC Tsumugi Drive 1.0.0

本書は`DiskClone_Development_Spec.md` v2.0の安全要件を、実装時に検査できる
境界へ落とし込む。過去の予約ジョブ、`.dcimg`、`.dcmig`の安全証跡は再利用できる
部品証跡であり、v2の製品経路が安全であることの代用にはしない。

## 1. 守る対象

1. コピー元ディスク、コピー元ボリューム、暗号化状態
2. 選択されていない物理ディスク、USB、ホストOS
3. 既存の完成イメージと利用者ファイル
4. 復元先・クローン先が未完了である事実
5. パスワード、BitLocker回復キー、シリアル、利用者パス
6. Microsoft配布物および第三者依存のライセンス境界

## 2. 脅威と失敗モデル

- 操作中のディスク番号・ドライブ文字・USBパス変更
- 同型番ディスク、空シリアル、偽装・不安定なUSBブリッジ
- 選択後の切断・再接続、容量・セクター・レイアウト変更
- VSS Writer異常、Snapshot消失、差分領域枯渇
- 読取りエラー、書込みエラー、短いI/O、flush失敗、読戻し不一致
- 停電、強制終了、利用者取消、アプリ例外
- `.tsumugi`の切詰め、差替え、改ざん、巨大値、未知フラグ、暗号認証失敗
- ADKインストーラー、Microsoft標準ツール、第三者依存の差替え
- ログや中断情報によるコピー元への意図しない書込み
- 旧ジョブファイルの誤検出・自動実行

## 3. 不変条件

### 3.1 コピー元と書込み先の型分離

- `ISourceDiskReader`はGeometry、安定識別、範囲読取りだけを公開する。
- `ITargetDiskWriter`は別型とし、対象無効化、書込み、flush、読戻し、最終確定を公開する。
- コピー元物理ハンドルは`GENERIC_READ`だけで開く。
- Windows版のSnapshot Readerは検証済みSnapshotデバイスパスだけを受け取り、元Volume GUIDを受け取らない。
- 物理ディスクへの`WriteFile`、属性変更IOCTL、パーティション最終確定は審査済み対象Writer以外に配置しない。
- コピー元安定識別と全ての書込み先安定識別が異なることを、計画時と書込み直前に確認する。

### 3.2 Windows版とWinPE版の無変更保証

- Windows版のアプリ自身は既定でコピー元物理ディスク、ボリューム、BCD、BitLocker状態へ書き込まない。
- Windows版ではOSとVSSの通常書込みを止められないため、「物理的に一切書き込まない」と表示しない。結果はSnapshot作成UTC時点と表示する。
- 詳細設定で同じ物理ディスクの選択対象外パーティションをイメージ保存先にする場合だけ、保存先へのアプリ書込みを例外として許可する。ディスク全体イメージ、保存先自身を含む選択、PEでは禁止し、毎回、故障対策にならないことと保存先が変更されることを警告する。
- WinPE版ではコピー元をOSレベルで読取り専用に固定し、その確認後にだけ処理を開始する。
- コピー元の完全無変更が必要な場合はWinPEを推奨する。
- EXEまたは`data`がコピー元物理ディスク上にある場合、実行中ログと中断チェックポイントをそこへ作らない。

### 3.3 安定識別

次を取得可能性と信頼度付きで保持する。

- デバイスインスタンスID／インターフェースパス
- モデル、ベンダー、容量、論理・物理セクター
- シリアル末尾と内部Hash
- BusType、リムーバブル、システム、offline、read-only
- GPT Disk GUIDまたはMBR署名
- パーティション方式、区画数、開始位置、長さ、型、ファイルシステム

ディスク番号、ドライブ文字、一覧位置だけでは一致としない。確認後、offline／online
変更後、物理ハンドル取得後、commit直前に再照合する。必須信号の未知、複数一致、
不一致は停止する。

USB筐体に一意シリアルがない場合は、同じ途切れない接続セッション中だけ、
パス／ポート／モデル／容量／レイアウトの複合識別を条件付きで許可する。
切断・再接続を検知した時点で計画と`OK`承認を無効にする。

## 4. 破壊操作の承認境界

クローン先消去、復元、USB初期化、起動修復で共通の二段階確認を使う。

1. モデル、容量、Bus、シリアル末尾、GPT／MBR、パーティション図、変更内容を表示する。
2. 大文字`OK`の完全一致を要求する。

対象固有の長い確認語は使用しない。確認を記憶、自動入力、別操作へ流用しない。
実行直前の再識別結果が確認画面と異なる場合は、`OK`済みでも停止する。

## 5. 統一トランザクション

### 5.1 実行順序

```text
read-only inventory
  -> OperationPlan
  -> preflight
  -> source session
  -> target authorization (OK)
  -> identity revalidation
  -> target offline / invalidation
  -> bounded writes
  -> per-write read-back
  -> flush
  -> global verification
  -> final metadata commit
  -> OperationResult
```

- コピー先が既存GPT／MBR／NTFS等でも、承認後に先頭・末尾識別を読戻し検証付きで無効化する。
- GPTは保護MBR、配列、副ヘッダーを検証後、主ヘッダーを最後に確定する。
- MBRは全データ検証後に有効な先頭MBRを最後に確定する。
- 途中失敗・取消時は部分対象を自動的に通常利用可能へ戻さず、未完了として保護する。
- システムクローン完了後のコピー先はofflineのまま保持する。

### 5.2 一時停止・取消

- 読取り／変換／データ書込み中は安全な境界で一時停止と取消を受け付ける。
- 最終パーティション表、BCD、NVRAM等の不可分commit中は取消不能を明示する。
- 取消時も既に行った書込みをflushし、完成メタデータを確定しない。
- Windows版はVSS差分領域を監視し、枯渇が迫った場合は放置継続を許さず、再開または安全取消を求める。

## 6. Windows VSS境界

- 対象となる全ボリュームを同一Snapshot setへ追加する。
- Writer metadata、PrepareForBackup、DoSnapshotSet、Writer状態、BackupComplete、Snapshot削除の順序を固定する。
- Snapshot ID、set ID、元Volume、Snapshotデバイス、Geometryを再検証する。
- NTFS BitmapとデータReaderは同じSnapshotから取得し、ライブVolumeと混在させない。
- Snapshot対象外の静的システム領域だけを読取り専用物理Readerから取得し、役割対応が一意でなければ停止する。
- Writer異常は既定停止。詳細設定でクラッシュ整合性を明示した場合だけ続行し、結果に永続記録する。
- Snapshot set作成後の全失敗経路で削除を試み、cleanup失敗を成功扱いしない。
- Snapshot消失、Geometry不一致、短い読取り、差分領域危険は停止または安全取消とする。

## 7. `.tsumugi`入力・暗号境界

### 7.1 不正入力

- `.tsumugi`は常に信頼できない入力として扱う。
- 固定ヘッダー、版、必須フラグ、位置、長さ、個数、加算、乗算、正規順序、重複を検査する。
- 未知の必須機能、暗号、KDF、圧縮、ファイルシステム意味を拒否する。
- 暗号化時は公開ヘッダーの範囲以外を復号・認証してから解析する。
- AES-GCM Tag、チャンクHash、全体Hashの不一致は対象書込み前に拒否する。
- 復元は書込み／削除共有なしの同一ファイルハンドルを完全検証し、そのハンドルだけを単回使用の復元元へ渡す。
- 復元直前に各非ゼロチャンクを再認証／再Hashし、最大チャンク以上をRAMへ保持しない。

### 7.2 暗号鍵

- KDFは承認済みArgon2id、内容暗号はWindows CNG AES-256-GCMに限定する。
- Saltはイメージごと、Nonceはチャンクごとに一意とする。Nonce再利用を生成側・読込側で拒否する。
- パスワード、派生鍵、平文一時バッファは最小寿命とし、使用後に明示消去する。
- パスワード、回復キー、鍵導出中間値をログ、クラッシュ情報、中断チェックポイントへ保存しない。
- 認証失敗理由から平文内容を推測できる詳細を通常UIへ出さない。

### 7.3 完成ファイル置換

- `.partial`は`CREATE_NEW`と保護DACLで作成し、reparse／ADS／UNC／デバイスパスを拒否する。
- イメージ保存先は既定でコピー元物理ディスクと分離する。同一ディスク例外では、Windows版、選択対象外の別パーティション、詳細設定の再確認を全て要求する。
- 既存完成ファイルを先にtruncate、上書き、削除しない。
- `.partial`のflush・検証後だけ、回復可能な同一ボリューム入替えを行う。
- 失敗時に削除できるのは、現在の実行が所有する中断チェックポイントと未完成出力だけである。

## 8. 単一中断チェックポイント

- 製品が認識する中断処理は最大1件とし、予約・スケジュール・一覧機能へ拡張しない。
- 処理種別、ソース／ターゲット安定識別、Snapshot ID、計画Hash、出力ファイルID、検証済み範囲だけを記録する。
- 同一Snapshot／ソース状態、同一接続、同一出力を証明できなければ再開を拒否する。
- 再開時は既に完了したチャンクもHash／認証を再確認する。
- 旧ジョブファイルは探索、読込み、変換、実行、削除しない。中断情報の候補にも扱わない。

## 9. 救出モード

- 標準モードは最初の読取り不能で停止する。
- 救出モードは有限回の前方／逆方向／小ブロック読取りを行い、無限再試行しない。
- 読めない範囲をゼロ埋めし、欠損マップへLBA／長さ／試行結果を記録する。
- 欠損が1バイトでもあれば結果を「一部欠損」とし、成功コード・緑色完了だけで表示しない。
- 救出時のターゲットは同容量以上のRAWクローンまたは`.tsumugi`救出イメージに限定し、縮小・形式変換を禁止する。
- システムディスク救出はWinPEだけ、Windows版は非システムデータディスクだけを許可する。

## 10. 起動修復境界

- 通常操作は対象ディスクだけを受け取り、Windows、ESP／Active、GPT／MBR、WinREを読取り専用で検出する。
- Microsoft標準ツールは絶対System32パス、通常ファイル、非reparse、Authenticodeまたはカタログ署名、`Microsoft Corporation`署名者を検証する。
- 実行引数は列挙済み固定値から組み立て、PATH検索、シェル文字列連結、利用者任意引数を許可しない。
- BCD新規再構築は、既存BCD退避、新規作成、新規BCD検証、成功時退避削除、失敗時部分BCD除去と復元を1トランザクションにする。
- ESP／システム領域の新規作成は、縮小可能NTFSと一意な配置を確認し、別の追加確認後だけ行う。
- 第三者EFIローダーは保持／削除を利用者に選ばせる。
- 「このPC向け」と明示された場合だけNVRAMを変更し、既存ブート順を不必要に破壊しない。他PC向けではESP内に限定する。
- WinREを安全に特定できなければ通常起動だけを修復し、部分修復と表示する。

## 11. BitLocker境界

- 元ディスクを完全復号する操作を本製品から行わない。
- Windows版は既にUnlockされたボリュームだけをSnapshot／ファイル経路で読む。
- WinPE版は利用者入力で一時Unlockし、資格情報を保存しない。
- コピー先は暗号化解除状態で完成させ、暗号化状態維持を成功条件にしない。
- 回復キー抽出、資格情報DB解析、パスワード回復、保護回避は実装しない。

## 12. ADK・WinPE・通信境界

- 製品ネットワーク通信は、利用者が開始したMicrosoft公式ADK取得とY-TEC手動更新確認だけに限定する。
- ADK取得はリリースごとの固定HTTPS URL、許可版、SHA-256、Microsoft署名者を全て検証する。
- Web検索やリダイレクト先から未検証の最新版を自動選択しない。
- 利用者へMicrosoft利用条件と取得内容を表示し、明示同意後にだけ取得する。EULA同意をアプリが代行しない。
- 一時ダウンロードは成功後に削除し、製品ZIP、リポジトリ、Y-TECサーバーへMicrosoft媒体を保存しない。
- 導入済みADK、ユーザーが作成したoffline layout、ローカル生成USB／ISOは利用者端末の資産として扱う。
- USBは安定識別と`OK`後にだけ初期化し、起動中レスキューUSB物理ディスクを全書込み対象から除外する。
- 手動更新確認は固定Y-TEC HTTPS URLの固定スキーマだけを読み、自動更新・自動ダウンロード・起動時通信を行わない。

## 13. 強制停止条件

- ソースとターゲットの一致、必須識別の未知／変化／複数一致
- 現在のWindowsシステムディスクをクローン／復元先に選択
- 起動中レスキューUSBを物理書込み先に選択
- Dynamic Disk、LDM、Storage Spaces、RAID、不正GPT／MBR、範囲重複
- 通常クローンの論理セクター不一致、縮小経路で解釈不能な対応領域
- コピー先容量不足、配置オーバーフロー、開始後の容量／Geometry変化
- 読取り、書込み、flush、読戻し、Hash、認証Tagの失敗
- VSS Writer既定停止条件、Snapshot消失、cleanup失敗
- `.tsumugi`の未知必須版／フラグ／暗号／圧縮、切詰め、重複、差替え
- 中断再開時のSnapshot／ソース／ターゲット／出力の同一性不成立
- Microsoftツール／ADKのパス、署名者、版、Hash、終了コード不一致
- 起動修復対象、ESP／Active、Windows、WinRE、NVRAM目的の不明
- コピー先健康状態の重大異常

## 14. 自動安全検査

安全境界検査スクリプトは少なくとも次を検査する。

- 物理`WriteFile`、`GENERIC_WRITE`、属性変更IOCTLの許可配置
- 旧ジョブの検索・読込・実行・削除APIが製品入口から到達しないこと
- 公開CLIに`--job-*`がないこと
- Microsoft媒体・ツールがリポジトリ／Portable ZIPへ含まれないこと
- ネットワークAPIの呼出し先がADK取得と手動更新確認に限定されること
- Argon2、Zstandard、LINE Seed JPの版・Hash・ライセンス・SBOM一致
- 機密値のログ禁止

自動検査はコードレビュー、VM、代表実機試験の代替ではない。
