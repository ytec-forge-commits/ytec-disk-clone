# `.dcimg` v1形式基盤（作業中）

> **廃止済み旧形式の履歴資料:** この形式は1.0.0正式版UI／CLIで使用できません。
> 公開変換機能も提供しません。現行形式は`image-format.md`の`.tsumugi` v1です。
> 以下は再利用した安全部品と試験証跡を理解するためだけに保持します。

## 状態

これはPhase 2向けの作業中形式です。製品リリース用の互換性確定版ではありません。現時点では、メモリ上のZstandard/非圧縮コンテナ作成に加え、再識別済みの読取り専用物理ディスクとVSS Snapshotから抽象ステージング先へ有界ストリーム出力し、全内容の再読込み成功後だけcommitする境界、安定識別/空き容量/reparse/非上書きを検査するWindows実ファイルステージング、不正入力を前提にした構造・SHA-256検証、MBR/GPTパーティション表スナップショット、厳格なバックアップマニフェスト、合成ターゲットへの検証済み復元を実装しています。Windows製品画面にはオンライン作成経路、ローカル`.dcimg`の有界完全検証、復元先候補確認、二段階確認、ハッシュ付き復元予約ジョブ保存を接続しました。WinPE製品CLIは復元ジョブの`.dcimg`完全再検証と復元先の容量/セクター/元ディスク分離に加え、ドライブ文字変更後に明示再選択したファイル、または固定/リムーバブル媒体の同じ相対パスから有界自動再解決したファイルを、ジョブ記録済みの長さ/全体SHA-256へ照合します。`--job-preflight`単体は復元先を開かず実行無効を固定しますが、別の製品`--job-execute`は同じ呼出し内で再検証と二段階確認をやり直した後に対象専用復元サービスへ進みます。作成は標準権限では物理ディスクを開く前に停止して自動UACを行いません。ライブVSSから実ファイルまでと物理復元の非圧縮製品経路VM試験は完了しています。Zstandardはメモリ/ストリーム/VSS製品接続のモック検証まで完了し、実VSS VM生成物の復元・起動回帰は未実施です。

検査成功は「実装済みのv1構造、マニフェスト意味、パーティション表、ハッシュが正しい」ことだけを示し、単独では物理復元許可にしません。合成復元境界でも、コンテナ全体、バックアップマニフェスト、パーティション表スナップショット、対象安定識別、システムディスク除外、容量、セクター、二段階確認を最初の書込み前にすべて検証します。製品WinPEプリフライトには既知LDM型/Storage Spaces除外、BitLocker完全復号、対応ファイルシステム、AC電源の三値判定まで接続しましたが、合格してもプリフライト単体では物理復元許可にしません。

## Windows復元前の有界検証

`inspect_dcimg_v1_from_reader`はファイル全体を一括保持せず、固定ヘッダー、
チャンク索引、フッター、マニフェスト、パーティション表スナップショット、
独立ハッシュ表だけを位置指定で読みます。全体SHA-256と非ゼロチャンクは
呼出側指定の上限以下に分割して再読込みし、ゼロチャンクは規定ハッシュを
検証します。最後にヘッダーとフッターを再読込みし、検証中に内容が
差し替わった場合も受理しません。

Windows製品入口は最大4 MiBの検証ブロックを使い、ローカルドライブ文字の
`.dcimg`通常ファイルだけを`GENERIC_READ`で開きます。reparse、ネットワーク、
デバイス、ドライブ直下、範囲外/128 MiB超の単発読取りを拒否し、各読取り前に
キャンセルを確認します。完全検証と共通意味ゲートに合格しても、
`restore_execution_enabled=false`を返し、復元先ディスクを開きません。

Windows GUIの復元先候補評価は、読み取り専用列挙結果と検証済み
マニフェストだけを受け取ります。安定識別、イメージ元との同一性、
現在動作中のWindowsディスク、読取り専用/リムーバブル/不明状態、
パーティション形式、容量、論理セクターを確認し、未知情報は拒否します。
候補合格時も`restore_execution_enabled=false`のままです。二段階確認後は
復元先を開かず、ハッシュ付き予約ジョブだけを新規保存します。WinPEAppは
このジョブを受け取るとディスク列挙前に同じ有界検証器で`.dcimg`全体を
再検証します。WindowsとWinPE間のドライブ文字変更はジョブ内の長さと
全体SHA-256に一致する手動再選択、または同じ相対パスを最大23候補に限定した
自動再解決で処理します。既知LDM型/Storage Spaces、BitLocker完全復号、
対応ファイルシステム、AC電源の基礎検査も行いますが、再起動保留の具体検査、
物理復元許可は後続入口の責務です。

## コンテナ順序

全整数はリトルエンディアンです。v1ではセクション間の隙間、順序変更、末尾データを許可せず、次の正規順序だけを受理します。

```text
[Fixed Header: 256]
[Manifest: 1..16 MiB]
[Partition Table Snapshot: 1..16 MiB]
[Chunk Index: chunkCount * 80]
[Stored Data Chunks]
[Hash Table: chunkCount * 32]
[Footer: 64]
```

固定ヘッダーは製品名に依存しない8バイトマジック、形式`1.0`、ディスク/セクター/チャンク寸法、圧縮プロファイル、6セクションの64bit位置/長さ、マニフェストSHA-256を持ちます。予約領域、未知フラグ、未知版、未知圧縮プロファイルは拒否します。

フッターは別マジック、フッター直前までの全体SHA-256、イメージ全長を持ちます。予約領域は0固定です。

## バックアップマニフェスト

マニフェストv1は固定192バイトヘッダー、80バイトのパーティション記録、
UTF-8文字列領域からなる正規リトルエンディアン形式です。最大16MiBで、
予約領域、オフセット、UTF-8、項目順、末尾データを検査し、解析後の
再エンコードが入力と1バイトでも異なる場合は拒否します。

次の意味情報をコンテナハッシュの対象として保持します。

- コピー元の安定識別、容量、論理/物理セクター。論理セクターは512/4096バイト、
  物理セクターは論理セクター以上の2の累乗かつ整数倍で、64KiB以下
- GPT/MBRとUEFI/Legacy BIOSの対応
- Windows 10/11 x64の版とビルド、作成UTC、アプリ版
- BitLocker完全復号済みゲート
- 圧縮方式/版、チャンクサイズ
- 全パーティションの表インデックス、範囲、役割、NTFS/FAT32、
  クラスタサイズ、名前

GPTはESP、MSR、Windows NTFSを必須とし、MBRはWindows NTFSを必須とします。
範囲重複、表インデックス重複、役割とファイルシステムの矛盾、未知形式、
未知の圧縮方式/版、BitLocker未復号を拒否します。作成時は生ディスクのNTFS/FAT32
ブートセクターを再解析し、`-FVE-FS-`署名を検出した場合はマニフェストを
生成しません。復元時はコンテナ寸法と全データチャンクが宣言済み区画内に
あることを、最初のターゲット書込み前に再検証します。

## チャンク索引

各80バイト項目は次を持ちます。

- コピー元ディスク上の64bit論理オフセット
- 未圧縮長、保存位置、保存長
- `zero_filled`フラグ
- 圧縮方式
- 未圧縮データのSHA-256

論理範囲は512/4096バイトセクター境界に揃え、16MiBまたは32MiB以下、コピー元容量内、昇順、非重複でなければなりません。保存範囲はデータセクションを先頭から末尾まで隙間なく一度だけ参照します。ゼロチャンクは保存位置/長さ0、圧縮なし、データなしとし、指定論理長のゼロ列SHA-256をWindows CNGで再計算します。

ハッシュ表は索引内SHA-256を独立して再掲し、1項目でも不一致なら停止します。非圧縮チャンクは保存長と未圧縮長の一致を要求します。Zstandardチャンクはプロファイル1の単一フレームだけを許し、辞書、連結/末尾データ、内容サイズ不明または宣言未圧縮長との不一致を拒否します。いずれも展開後データでSHA-256を確認します。

## 抽象ステージングの確定順序

`write_verified_dcimg_v1`は、Windowsファイルや製品保存先へ接続可能な抽象I/O境界です。コピー元と出力先を別型にし、処理順序を次に固定しています。`write_verified_uncompressed_dcimg_v1`は非圧縮互換入口です。

1. マニフェスト、パーティション表スナップショット、コピー元Geometry、全チャンクの整列・範囲・重複を、出力開始前に検証する。
2. Zstandard時は非ゼロチャンクをコピー元から各1回だけ読み、level 3で圧縮する。小さくならないチャンクは非圧縮へ戻し、予約した上限長のステージングへ順次保存する。
3. 正規オフセットのヘッダー、マニフェスト、スナップショット、索引、独立ハッシュ表を書き、ステージングを正規最終長へ縮小して`flush`する。
4. 全索引、独立ハッシュ表、全非ゼロチャンクをステージング先から再読込みし、必要なら展開して各SHA-256を検証する。
5. フッター直前までを有界単位で再読込みして全体SHA-256を計算し、フッターを書いて共通の不正入力検査器で全件再検証する。
6. すべて成功した場合だけ`commit_verified`を呼ぶ。
7. `begin`以降のwrite/read/flush/hash/footer/commit失敗では`abort_incomplete`を呼び、abort失敗も成功扱いしない。

ストリーム出力は既存のメモリ作成結果とバイト単位で一致することをモックで確認しています。Windows具体Backendは、ローカルドライブ上の絶対`.dcimg`だけを受け付け、保存先ボリュームを物理ディスクへ対応付けます。開始時と確定前に同じ再列挙結果へコピー元/指定コピー先/保存先を一意に対応付け、相互の同一性を拒否し、空き容量、全親要素のreparse不使用、完成/未完了ファイルの不存在を確認します。保護DACL付き`CREATE_NEW`で`.partial`だけを所有し、write-through、全長予約、読戻し、flush後に所有中ハンドルの`ReplaceIfExists=FALSE`改名で完成名へ確定します。失敗時は今回所有した`.partial`だけを削除し、開始前から存在したファイルは触りません。電源断耐性と中断再開はまだ保証しません。

## 現在の上限と安全側の拒否

- チャンク数は最大1,048,576
- マニフェストとパーティション表スナップショットは各16MiB以下
- すべての加算・乗算・範囲を検査
- 切詰め、末尾追加、重複論理範囲、重複保存位置、未知フラグ、予約領域非ゼロを拒否
- マニフェスト、索引/ハッシュ表、チャンク、全体のどれか1バイトでも不一致なら拒否
- Zstandardは公式v1.5.7、プロファイル1だけを許可。level 3、単一フレーム、辞書なし、内容サイズ/チェックサムありに固定
- 圧縮データの破損、辞書ID、連結/末尾フレーム、内容サイズ不明/不一致、展開上限超過を拒否

## パーティション表スナップショット

スナップショットv1は64バイト固定ヘッダー、最大8個の64バイト領域記録、領域データを正規順序で保持します。各領域はディスク上オフセット、長さ、SHA-256を持ち、セクター整列、容量内、昇順、非重複、予約領域0を要求します。

- MBRはディスク先頭の論理セクター1個だけを保持する
- GPTは先頭側領域とディスク末尾側領域の2個を保持する
- GPT先頭領域はオフセット0、末尾領域はコピー元容量の末端で終わる
- コンテナとスナップショットのコピー元容量/論理セクターが一致しなければ拒否する

領域SHA-256は格納時に再計算し、復元時にも全領域を再検証します。渡されたハッシュ値を信頼しません。

## 合成復元の確定順序

`restore_verified_dcimg_v1`と`restore_verified_dcimg_v1_from_reader`は、
物理ディスクを直接探索しない合成I/O境界です。製品のWinPE復元サービスは
別層で対象を再識別し、同一ハンドルの準備済み復元元と物理I/Oアダプターだけを
この境界へ渡します。Reader版はイメージ全量ではなく、索引・メタデータと
復元中の1チャンク（最大32MiB）だけを保持します。処理順序を次に固定しています。

1. `.dcimg`全体、全チャンク、独立ハッシュ表、全体ハッシュを検証する。
2. バックアップマニフェストの正規形とジョブ意味を検証する。
3. パーティション表スナップショットの意味と領域ハッシュを検証し、
   マニフェストと形式/寸法を照合する。
4. 復元先の安定識別、非システム、容量、セクター、二段階確認を検証する。
5. 全データチャンクが宣言済み非MSR区画内にあり、パーティション表領域と
   重複しないことを、最初の書込み前に確認する。
6. パーティション表領域を無効化し、読戻しとflushを行う。
7. Reader版は非ゼロチャンクを復元直前に再読込みし、Zstandardなら最大32MiBへ
   有界展開して記録済みSHA-256を照合する。展開後/非圧縮/ゼロデータを
   分割書込みし、各回読戻し検証する。
8. データflush後、パーティション表を最後に確定する。GPTは末尾側を先、
   先頭側を最後にする。
9. 最終flush成功時だけ完了報告を返す。

破損イメージ、確認不一致、容量不足、チャンク/パーティション表重複、
Reader例外/短い読取り/検証後の内容変化、読戻し不一致はすべて
パーティション表確定前に停止します。全体検証中のキャンセルは
ターゲットへの最初の書込み前に停止します。
