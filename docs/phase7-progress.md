## 今回実装した非UAC範囲

- Windows GUIへ「環境確認→形式・出力先→内容確認→作成」の
  4段階レスキューメディアウィザードを追加
- ADK/WinPE Add-on、Microsoft署名、検証済み版/必須更新の
  読み取り専用診断が合格するまで選択工程を無効化
- ISOファイル（推奨）とUSBメモリ（全内容消去）を明示的に分離
- BIOS/UEFIとSecure Boot 2011 CAの互換性重視プロファイル、
  `/bootex`を必須とする2023 CAプロファイルを明示的に分離
- ISO出力はドライブ文字付きローカル絶対パス、`.iso`拡張子、
  `.`/`..`なし、既存ファイルなしをGUI段階で確認
- USB候補は列挙済み情報だけから、非システム、USB Bus、
  取り外し可能、オンライン、非読み取り専用、既知の基本GPT/MBR単一区画、
  または区画のないRAW/GPT/MBR、安定識別可能をすべて要求
- USB要約にディスク番号、モデル、容量、シリアル末尾、
  全削除パーティション数、短い確認語`OK`を保持
- 内容確認まではISO/USBを開かず、ファイル作成、ディスク書込み、
  UAC要求を一切行わない
- 管理者として手動起動した配布版だけが、固定配置した自作スクリプト/
  診断CLI/WinPE CLI/GUIとSystem32の署名済みWindows PowerShellを再検証し、
  ISO製品サービスへ進む。サービス自身はUACを要求しない
- GUIで選んだ完成`.iso`/manifestと新規一時作業フォルダーを分離し、
  既存ファイルを上書きせず、完成ISOを4 MiB単位で全量SHA-256検証
- 作業領域、ADK媒体、WIMマウント、日本語化、製品照合、WIM確定、
  ISO生成、公開、全量検証を実進行としてGUIへ通知
- 進捗率、経過時間、目安残り時間、完成パス、容量、SHA-256、
  manifestと監査用作業領域を結果画面へ表示
- USBは対象詳細確認1/2と確認語`OK`入力2/2の後にも、同一呼出し内で
  安定識別、ディスク番号、許可した区画数、既存または予約ドライブ文字を再確認する
- 消去した旧ボリュームのアクセスパスが予約文字へ残った場合は、初期化後に
  `Get-PSDrive`/`Get-Volume`を再確認して別の未使用文字を選び、実割当文字を
  同じ物理USBとしてC++側でも再照合する
- ローカルADKのMicrosoft公式`MakeWinPEMedia.cmd /UFD /F`だけを使い、
  PATHを署名確認済みADKツールとSystem32へ限定して選択ボリュームを作成する
- USB書込み直後に対象を再識別し、USB上の全媒体ファイルを元媒体と
  長さ/SHA-256で全量照合する。`boot.wim`、BIOS/UEFI起動ファイル、
  監査manifestの確認後だけ成功扱いにする
- 静的MSVC x64の自作10ファイルだけを含むポータブルZIPを非上書き生成し、
  UTF-8 SHA-256一覧、日本語ファイル名、全ハッシュ、禁止媒体不在を実体監査

## 自動テスト

`ytec-media-wizard-tests`で次を実ディスクなしに確認します。

- ADK未確認または作成不許可なら手順1で停止
- 2023 CA選択時に`/bootex`未確認なら停止
- 正常なローカルISOパスと大文字拡張子を許可
- 相対、UNC、`..`、非ISOパスを拒否
- 正常USBだけが安定識別と確認語`OK`を持って内容確認へ進む
- システムディスク、不明状態、非USB、読み取り専用、
  安定識別不足を安全側に拒否
- 複数パーティション、不明形式、確認情報なし、書込み直前の個体交換、
  ドライブ文字変更、不完全な完了報告、書込み後の個体交換を拒否
- USB対象を実行前と実行後の2回照合し、正しい対象だけが実行サービスへ
  1回渡ることを実ディスクなしで確認
- 区画のないGPT USBへ未使用ドライブ文字を提案し、初期化後にその文字が
  使用中なら別の文字へ切り替え、作成後の実ボリュームとして再照合することを
  実ディスクなしで確認
- 偽の`Z:`と存在しないディスク番号を指定したUSB事前診断が成功し、
  `-BuildMedia`なしでは作業フォルダーもUSBアクセスも開始しないことを確認

## elevated実測結果と残件

- 2026-07-31に利用者が管理者として手動起動したポータブル版から
  製品ISOサービスを実行し、環境再検査、ADK媒体準備、WIMマウント、

- ISO生成後のmanifest保存で、Windows PowerShell 5.1が
  `-Encoding utf8NoBOM`を受け付けず終了コード1となる不具合を確認
- manifest保存を.NETのUTF-8 BOMなし書込みへ変更し、製品画面にも
  PowerShell標準エラーの有界な診断末尾を表示する回帰防止を追加
- 失敗時に保持した中間2023 CA ISO
  （429,881,344バイト、
  SHA-256 `4D64183F3BAF4A7D723F396798AB315B880B4445E4E546FDF6CB79AA345751CA`）
  は、NIC/仮想ディスクなし専用VMでLegacy BIOSと
  UEFI64/Secure Boot有効の双方から日本語GUI自動起動まで確認
- WinRE読み取り専用CLIを含む最新ポータブルZIP
  `%TEMP%\Y-TEC-Tsumugi-Drive-package-20260731-143023.zip`
  （3,456,979バイト、SHA-256
  `460152725A6C950A648AB155E2223CEA567F08697441720AAF72B0F801FF6C76`）は、
  10ファイル/9ハッシュ、Microsoft媒体不在の実体監査に合格した
- 同ZIP内のWindows PowerShell 5.1事前検証はADK `10.1.26100.2454`、
  DISM `10.0.26100.8972`、`KB5101684`で合格し、出力先を作成しなかった。
  配布版WinPE CLIの`--help`でもWinRE診断コマンドと書込みなし境界を確認した

- 成功/失敗時のWIM unmount/discardと、製品が新規作成した一時作業領域だけの

  6条件回帰を完了

UAC無効化、自動承認、署名回避、Microsoftファイルの製品同梱は行いません。
ISO製品サービスのelevated処理はmanifest発行と完成名への非上書き確定まで
実測済みです。2026-08-01午前の2011 CA版は429,942,784バイト、SHA-256
`B0B82226323A7F55F82DC35C677184F68533A968B9F53E932BB60FD3A381F19A`、
2023 CA版は429,942,784バイト、SHA-256
`05302CF7B2F9B7C3E398C7A95B4D8C35D4500D6F3F742C8149F3E93163BD350E`です。
その後にLINE Seed JP埋込みとOFL本文同梱を追加したため、現在差分では
ISO再生成と同じ6条件の起動回帰を残します。
USB実作成エンジンは製品GUIへ接続し、ISOとは別の進捗・完了結果を表示します。
対象限定、二段階確認、実行前後の再照合、全ファイル読戻しはモックと
非書込み境界試験に合格しました。実USBへの破壊的実行はまだ未検証です。

## WinPE製品画面

非UAC範囲で`ytec-winpe-gui.exe`を追加しました。

- Tsumugiの3色の糸、暗色サイドバー、白い操作カードを使う独自Win32画面
- 「予約ジョブ」「起動修復のみ」「ディスク診断」の3機能を初期画面から操作
- ジョブ選択→完全検証→対象再確認→実行の4段階表示
- 起動修復の対象選択→読取確認→最終確認→修復完了の4段階表示
- 予約ジョブは既存のSHA-256、`.dcimg`完全検証、安定ディスク再識別を再利用
- 起動修復は割当済みWindows/システム領域の読取検査と対象固有語を要求
- システムディスク、不明属性、リムーバブル、読み取り専用候補を対象から除外
- 1280x720のホスト実画面で3画面を確認し、表示漏れと1行一覧連結を修正

メディア作成スクリプトは静的CLI/GUIを別々にAMD64 PE32+、
固定System DLL、SHA-256で検査し、通常製品媒体ではGUIを自動起動します。
日本語表示用にはローカルADKの`WinPE-FontSupport-JA-JP.cab`を
DISMで追加する設計とし、事前診断はパス、非reparse、サイズ、SHA-256だけを
確認します。実際のWIM追加、完成ISO/manifest発行、Legacy BIOS、UEFI、
Secure Boot 2011/2023 CAの6条件起動はLINE Seed追加直前版で確認済みです。
現在差分の再生成だけを次の手動UACへ保留しています。
