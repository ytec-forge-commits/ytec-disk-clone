# 【廃止済み・正式版で使用不可】WinPEジョブ引き継ぎ形式 v4

> **履歴資料です。予約ジョブ方式は1.0.0正式版で完全廃止しました。**
> Windows版／WinPE版の製品UI・CLIは、この形式を検索、読込、変換、実行、
> 移動、上書き、削除しません。以下は旧v2／v3／v4の安全部品と試験証跡を
> 理解するためだけに保持しており、現行の操作手順・製品仕様ではありません。

## 目的

Windows版で選択・確認したジョブをWinPEへ渡すための、改ざん検知付き
UTF-8 JSON形式です。形式の生成・検証、WinPEでの読み取り専用
プリフライト、クローン/復元の明示的な製品予約ジョブ実行を実装しています。
WinPE GUI起動時の固定名ジョブ自動検出、読み取り専用プリフライト、
Windows側で明示選択したジョブだけの一回限り自動実行を実装しています。
Windows版の「ログ・診断」は固定位置の結果ログを
読み取り専用で検出・厳格検証し、最新結果を表示します。破壊的処理の
無条件自動開始とWindowsからの自動再起動は有効化していません。

## 安全境界

- 最大64 KiB
- UTF-8、項目名、項目順、数値表現、空白を含む正規形を固定
- payload全体をWindows CNG SHA-256で検証
- 未知項目、欠損、末尾データ、非正規エスケープ、ハッシュ不一致を拒否
- ディスク番号を同一性判断に使わず、モデル、容量、論理セクター、
  シリアル末尾、デバイスインスタンスIDをWinPEで再照合
- パスはローカル絶対Windowsパスだけを許可し、UNCを拒否
- ジョブファイルの具体ローダーは通常ファイルを`GENERIC_READ`だけで開き、
  reparse point、ディレクトリ、読取り中の長さ変更を拒否
- GUIの自動検出はC:～Z:の固定/リムーバブル媒体（X:を除く）にある
  `Tsumugi-clone-job.json`/`Tsumugi-restore-job.json`を、ドライブ直下または
  `Tsumugi`直下だけで最大92候補として確認する。再帰探索は行わず、
  候補重複、複数の有効ジョブ、1件でも不正な固定名候補があれば自動選択しない
- GUIでの確認後は承認済みpayload SHA-256へ実行時ローダーを固定し、
  確認から実行までに正規ジョブへ差し替えられた場合もディスク列挙前に拒否
- v3/v4の`executionMode`はpayload SHA-256の対象で、既定値は
  `review-required`。Windows側の二段階確認画面で既定OFFの選択肢を明示的に
  選んだクローン/復元だけが`auto-once`になる。v2は常に手動確認へ割り当てる
- v4の`transferMode`もpayload SHA-256の対象で、`exact`（通常モード）または
  `shrink`（縮小移行モード）を固定する。旧v2/v3は`exact`へ割り当て、後から
  縮小移行ジョブとして解釈しない
- `auto-once`はプリフライト合格後、ジョブpayload SHA-256を完全名に含む
  `.claim`をジョブ横へ`CREATE_NEW`で保存し、flush/全バイト読戻し後にだけ
  実行へ進む。既存記録、読取り専用媒体、保存失敗は自動実行を止める
- 開始記録は電源断や短い書込みでも削除しない。存在自体を再実行防止境界とし、
  同じジョブを二度自動実行しない。停止後は手動再確認または新しいジョブ作成が必要
- Windows版の具体ライターはジョブ全体を保存前に検証し、ローカル絶対
  `.json`パスへ`CREATE_NEW`で作成する。既存ファイルは置換しない
- ライターはflush、サイズ/全バイト読戻し、payload SHA-256再検証に成功した
  場合だけ完了し、失敗時は自身が新規作成した未完了ファイルだけを削除
- ジョブプリフライトは`executionEnabled=false`を固定
- パス値はプリフライト出力へ記録しない
- 復元ジョブはディスク列挙前に、指定`.dcimg`の全体、全チャンク、
  メタデータ、復元領域を共通ImageFormat検証器で読み取り専用再検証する
- 復元ジョブへ検証済み`.dcimg`のファイル長とコンテナ全体SHA-256を保存する
- WinPEでドライブ文字が変わった場合は`--image-path`による明示的再選択を許可し、
  完全検証後のファイル長と全体SHA-256がジョブ記録値と完全一致する場合だけ進む
- `--search-image`は固定/リムーバブル媒体の同じ相対パスだけを最大23候補として
  列挙し、再帰検索やパス推測を行わず、完全検証と同じ指紋の一致後だけ採用する
- クローン/復元の実行試行後は、ジョブと同じフォルダーへ時刻付き`.log`を
  `CREATE_NEW`で保存する。ジョブpayload SHA-256、種別、PASS/FAIL、完了UTC、
  製品版、詳細長/詳細SHA-256を記録し、flushと全バイト読戻しに成功した場合だけ
  保存済みと表示する。既存ログやジョブ本体は置換しない
- Windows版は同じ固定/リムーバブル媒体のドライブ直下と`Tsumugi`直下だけを
  最大256候補で読み取り専用列挙する。正規UTF-8、項目順、値、詳細長、
  詳細SHA-256、完全再生成、ファイル名のジョブ種別/完了UTC一致をすべて検証し、
  1件でも不正/重複/読取り不能なら部分的な成功結果を表示しない

SHA-256は真正性や署名者を証明するものではなく、作成後の偶発的・意図的変更を
検出するためのものです。利用者以外によるジョブ差替えまで防ぐ必要が生じた場合は、
鍵管理と署名方式を別の人間確認ゲートで設計します。

## payload項目

| 項目 | 内容 |
|---|---|
| `schemaVersion` | 現在は`4`。旧`2`/`3`は厳格な旧形式として読込み互換 |
| `jobType` | `clone`、`create-image`、`restore-image`、`mbr-to-gpt` |
| `source` | コピー元の安定識別。不要な種別では`null` |
| `target` | コピー先の安定識別。不要な種別では`null` |
| `imagePath` | イメージのローカル絶対パス。不要な種別では空文字 |
| `restoreImageIdentity` | 復元時の`lengthBytes`と`globalHashSha256`。他種別では`null` |
| `requestedConversion` | `preserve`または`mbr-to-gpt` |
| `transferMode` | v4のみ。`exact`（通常）または`shrink`（縮小移行）。v2/v3は`exact` |
| `createdUtc` | `YYYY-MM-DDTHH:MM:SSZ` |
| `appVersion` | 作成したアプリの版 |
| `executionMode` | v3/v4。`review-required`または`auto-once`。v2は前者へ固定 |
| `destructiveTargetConfirmed` | コピー先消去の二段階確認済み状態 |

外側の`jobHashSha256`は、正規形payloadの32バイトSHA-256を大文字16進64文字で
格納します。完全な構文は自作シリアライザが一意に生成し、パーサーは同じ正規形へ
再生成できない入力を拒否します。

## WinPEプリフライト

```powershell
ytec-winpe-app --job-preflight `
  --job-path E:\Tsumugi\job.json --text
```

ドライブ文字が変わった場合は、WinPEで見える現在のパスを明示します。

```powershell
ytec-winpe-app --job-preflight `
  --job-path E:\Tsumugi\job.json `
  --image-path F:\Backups\system.dcimg --text
```

この処理はジョブ検証、全ディスクの読み取り専用列挙、安定識別による再解決、
コピー先のシステム/読取り専用/removable/論理セクター確認までを行います。
復元ジョブではジョブSHA-256の検証後、ディスク列挙より前に`.dcimg`を
完全再検証します。続けて復元先容量、論理セクター、イメージに記録された
元ディスクとの分離を確認します。WindowsとWinPEでドライブ文字が変わる場合は、
利用者が再選択した`.dcimg`を完全検証し、ジョブ内の長さと全体SHA-256へ
照合します。`--search-image`を指定すると、C:～Z:（WinPEのX:を除く）の
固定/リムーバブル媒体で同じ相対パスだけを有界列挙します。任意フォルダの
再帰探索は行いません。さらに、検証済み
マニフェストのBitLocker完全復号/対応ファイルシステム、列挙結果の既知LDM型/
Storage Spaces、`GetSystemPowerStatus`のAC状態を三値で判定します。不明な
必須項目は不合格です。Windows Update／再起動保留は仕様どおり警告項目で、
現段階では`unknown`を表示します。必須検査がすべて合格しても、この
プリフライトは`executionEnabled=false`を固定し、書込み可能とは判定しません。

WinPE GUIは初回ディスク診断が安全に完了し、利用者がジョブパスをまだ指定して
いない場合だけ、上記固定候補をバックグラウンド検出します。一意な正規ジョブが
見つかった場合は自動でこのプリフライトまで進みます。`review-required`と旧v2は
対象消去のチェックと確認語`OK`の入力なしに開始しません。`auto-once`だけは、
Windows側で対象詳細と確認語`OK`による二段階確認と既定OFFの自動実行選択を済ませた
意思をハッシュで再検証し、一回限り開始記録の確定後に同じ実行境界へ進みます。

## WinPE予約ジョブ実行

`--job-execute`はクローン/復元ジョブだけを受け付け、プリフライト結果を
そのまま書込み許可へ昇格しません。同じ呼出し内でジョブ、安定識別、
実行直前安全条件、対象消去承認、対象固有の確認トークンを再検証します。
クローンは対応する基本GPT/MBR区画、固定/オンラインのコピー元、
空RAWまたは既知の基本GPT/MBR固定コピー先、既知BusType、同容量以上、512バイト論理セクターを要求し、
コピー元の同じ読取り専用ハンドルを保持してからコピー先だけをoffline化します。
復元は書込み/削除共有なしの同じ`.dcimg`ハンドル上で全体を再検証した後、
復元先だけをoffline化します。いずれも失敗/中止時は対象をonlineへ戻さず、
全読戻しと表確定が成功した場合だけライターを閉じてonlineへ戻します。

履歴上の直接`--clone-execute` VMハーネスは退役しました。現行の製品CLIは
読取り専用の列挙／プリフライトだけを受け付け、破壊操作は製品GUIからだけ開始します。
製品予約ジョブ経路は専用VMで成功/中止/破損拒否まで確認済みですが、
現在差分のISO再生成/起動回帰と実機試験前のため、一般利用可能とは扱いません。

## Windowsから起動環境への移動

ジョブ保存後、Windows 8以降かつアプリを管理者として手動起動済みの場合だけ、
Microsoftの詳細な起動オプションへ再起動するかを既定「いいえ」で確認します。
Windows標準`InitiateShutdownW`へ`SHUTDOWN_RESTART_BOOTOPTIONS`を渡し、
`SE_SHUTDOWN_NAME`を現在プロセス内だけで一時有効化します。UACの自動表示、
BCD/NVRAM/BootNext変更、別ユーザー/アプリの強制終了は行いません。
標準権限またはWindows 7では再起動サービスを呼ばず、通常再起動とBoot Menuの
手順を表示します。USBの選択は機種依存のため、詳細起動オプションの
「デバイスの使用」または電源投入直後のBoot Menuで利用者が行います。

- payloadの1バイト変更
- ハッシュ変更
- 末尾空白
- 先頭ゼロ等の非正規数値
- 不正UTF-8
- 64 KiB超過
- 二段階確認未完了

- UNCイメージパス
- WinPE再列挙でシリアル末尾が変わった対象

- 復元イメージ検証失敗または検証サービス不在時にディスク列挙へ進まないこと
- 再選択した同一イメージを受け入れ、長さまたは全体SHA-256が異なる
  別イメージはディスク列挙前に拒否すること
- 自動再解決がドライブ文字だけを置換し、X:を除外し、別指紋を読み飛ばして
  一致候補だけを採用し、一致なし/64候補超過ではディスク列挙前に停止すること
- ジョブ自動検出が固定名/固定位置だけを列挙し、X:を除外し、候補なしを正常に
  扱い、重複/複数/改ざん候補を自動選択しないこと
- 事前確認済みジョブを別の正規ジョブへ差し替えても、承認済みpayload
  SHA-256との不一致で物理I/O前に停止すること
- 結果ログがジョブハッシュと詳細SHA-256を含み、64 KiB上限、時刻付き新規名、
  全バイト読戻し、既存非上書きを守ること
- Windows側の読取り専用取込みが固定ディレクトリ/固定名だけを扱い、
  検証済み完了UTC順に並べ、改ざん、追記、名前と内容の不一致、重複を拒否すること
- 実行直前安全判定で、未接続検査を`unknown`のまま必須合格にせず、
  MBR LDM型`0x42`、Storage Spaces BusType、未知BusTypeをそれぞれ
  危険／危険／不明として扱うこと
- 全必須項目合格と、再起動保留の警告`unknown`を区別し、どちらの場合も
  プリフライト単体では物理復元を有効化しないこと
- 正常な復元ジョブでイメージ検証後にだけ復元先を再解決し、
  `imageVerified=true`かつ`executionEnabled=false`を返すこと
- 不正ジョブをファイルとして作成しないこと
- 新規保存成功後、同じパスへの再保存を拒否して元ファイルを維持すること
- v4 `transferMode`とv3/v4 `auto-once`がハッシュ対象として往復し、v2が常に
  `review-required`へ、v2/v3が常に`exact`へ読み込まれること
- v2へ自動実行指定、v2/v3へ縮小移行指定を混入できないこと
- 同じpayload SHA-256の開始記録は最初の`CREATE_NEW`だけ成功し、2回目、
  相対パス、保存不能では自動実行へ進めないこと
- Windows GUIで作成した一時ジョブを製品WinPEAppが読み取り専用で検証し、
  現在のコピー元／コピー先へ安定識別で再解決できること
- クローン予約ジョブが再列挙後の正しいコピー元/コピー先と空の許可語だけを
  製品サービスへ渡し、不正な確認語ではサービスを呼ばないこと
- クローン製品サービスの不完全な完了報告を成功扱いしないこと

## 2026-08-28 公開前候補の引継ぎ

この資料の旧予約ジョブ仕様は廃止済みであり、現行製品の操作経路では使用しない。
公開前候補の最新状況は次のとおりである。

- `1.0.0-internal-beta` のPortable候補をローカル生成し、ZIP SHA-256、内部Hash、
  Microsoft媒体非同梱、SBOM、依存ライセンス、安全境界を確認済み。
- 通常／静的MSVC／ASanの127/127 CTest、v1 Golden corpus、固定seedおよび
  coverage-guided ImageFuzz、Codex Securityの作業ツリー差分監査はPASS。
- 日本語操作マニュアルのMarkdown、DOCX、PDFを生成し、DOCX/PDFの目視・本文・
  プレースホルダー・アクセシビリティ監査を完了した。DOCXのアクセシビリティ監査は
  高重要度0件で、残る6件は警告枠・コード枠を1セル表として検出した中重要度の誤検知。
- 24H2クリーンVMはNIC・USB無効、EFI/Secure Boot、80GiB空VDIで構成したが、提供ISOと
  VirtualBox無人導入の組合せで初回OS起動が`evbda.sys`／`0xc0000098`となった。
- 保存済みWindows 10 22H2／Windows 11 25H2基底スナップショットから作ったリンククローンは、
  NIC、USB、共有クリップボード、drag and dropを無効にして1台ずつ使用した。両OSでADK未導入と
  未導入検出の安全停止を確認した。Guest ControlからEXEを直接起動すると`0xc0000374`を返すが、
  `cmd.exe`を親にする同じ隔離経路で現行静的CRTのADK／媒体／`.tsumugi`対象7テストは両OSともPASSした。
  直接EXE起動はVirtualBox Guest Control固有の互換性制約として記録し、対象VM回帰はPASSとする。
  基底VM・Kaspersky VM・物理媒体は変更していない。
  OS受入、ADK未導入クリーンVM、代表実機、実USBは未完了であり、正式版・公開バイナリ
  として扱わない。
- SignPathコード署名申請は審査待ち。候補バイナリは`NotSigned`であり、GitHub Releases
  またはWebへ公開しない。commit、push、公開は人間の明示承認後にだけ行う。
