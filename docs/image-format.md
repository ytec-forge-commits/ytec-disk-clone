# `.tsumugi` v1イメージ形式

更新日: 2026-08-10

正式版1.0.0のイメージ形式は、単一ファイル`.tsumugi` v1である。通常イメージ、
縮小移行、パーティション選択、任意暗号化、救出時の欠損Mapを同じコンテナで
表現する。

> 通常作成・復元の一部とWindows非systemデータ／WinPE救出イメージ作成は製品経路へ
> 合成接続済みだが、全VM／実機受入、リリース監査は未完成である。
> この文書は形式と安全契約を示し、現時点の一般利用可を表明しない。

## 形式方針

- 拡張子は`.tsumugi`
- NTFSまたはexFAT上の通常ファイルだけを正式対応
- FAT32向け4GiB分割は実装しない
- v1 Readerの後方互換性を今後の製品版で維持
- 未知の必須機能、暗号、圧縮、範囲外、重複、非正規順序を拒否
- 既定チャンクは16MiB以下
- 圧縮はZstandard 1.5.7。小さくならないチャンクは非圧縮へ戻す

## 論理構造

```text
[bounded public header]
[encrypted-or-plain manifest]
[partition/layout records]
[chunk index]
[chunk payloads]
[bad-range map]
[verification footer]
```

公開ヘッダーは形式判定、版、必須機能、KDF／暗号の最小情報だけを持つ。
暗号化時はディスク名、パーティション、内容索引を含むマニフェストも暗号化する。
位置、長さ、個数、加算、乗算、重複を64bit境界で検査し、宣言外データや末尾追加を
受け入れない。

マニフェストは少なくとも次を結び付ける。

- コピー元のモデルHash、シリアルHash、Source state Hash
- 論理／物理セクター、ディスク容量、GPT／MBR
- パーティションの役割、範囲、ファイルシステム、選択状態
- 通常／縮小、最小復元容量、起動方式、欠損Map
- チャンク範囲、保存方式、平文長、保存長、Hash／認証情報

異なるVSS Snapshot setや別のPE read-only epochを混在させない。全非ゼロチャンクは
同じ`ITsumugiImageSourceSession`から読み、明示ゼロチャンクだけSource Readerを
持たない。

縮小用WIMはファイルのバイトストリームであり、payloadの長さとチャンク境界を
論理セクターへ丸めない。一方、未対応ファイルシステムの`exact RAW`は元区画の
全バイトを保持し、payload境界、Source offset、復元先を論理セクターへ整列する。
未知のencoding、範囲外、復元先不足は推測で補正せず拒否する。
縮小時のpayload logical offsetはコンテナ内の重複しない名前空間であり、元ディスク
位置は別のsource offsetへ保持するため、`exact RAW`でも両offsetの一致は要求しない。

## 救出欠損Mapと読取り証跡

救出イメージの読取り不能範囲は`unreadable_zero_filled`チャンクとして表し、通常／縮小
イメージには記録できない。新しく作成する救出イメージは、公開ヘッダーの必須機能に
`unreadable_range_map`と`rescue_read_evidence`を両方立てる。未知のReaderは後者を
理解できないため安全に拒否し、対応Readerは各欠損チャンクの次の証跡を検証する。

- 前向き、逆向き、セクター単位の試行回数。各値は1以上
- 各段階で最後に観測したWindows native error
- 失敗範囲をゼロ埋めした後の読戻し確認済みフラグ

証跡は112バイトのチャンク索引record内、従来予約領域だったbyte 96～111へ格納する。
byte 96～98は各試行回数、byte 99のbit 0はゼロ埋め読戻し確認、byte 100～111は
3個の32bit little-endian native errorである。証跡のないチャンクは全16バイトをゼロに
保つ。メタデータ認証またはコンテナ全体Hashがこの範囲を保護する。

拡張前に作られた、`unreadable_range_map`だけを持ちbyte 96～111がゼロの救出画像は
後方互換のため読取り可能とする。ただし証跡なしとして扱い、新規writerは生成しない。
必須機能と欠損チャンク／証跡の有無が一致しない場合や、試行回数ゼロ、未確認の
ゼロ埋めは不正形式として拒否する。

全範囲を回収できた救出実行も`rescue`分類を維持して作成できる。この場合は欠損Mapと
読取り証跡の必須機能を立てず、`partial_loss=false`とする。通常モードへ読み替えず、
製品UIは救出モードで実行した事実を別に表示する。

## 暗号化

- KDF: Argon2公式参照実装20190702のArgon2id
- 既定: メモリ64MiB、反復3、並列度1、画像ごとの16バイトSalt
- 内容暗号: Windows CNG AES-256-GCM
- チャンクごとに一意Nonceと認証Tagを割り当てる
- パスワードと鍵素材は使用後に明示消去する
- パスワードは8文字以上のASCII印字文字
- 弱いパスワードは警告後に続行可能
- 回復キーは設けず、紛失時は復元不能と表示する

暗号化していないイメージはAES-GCMメタデータ認証を要求せず、マニフェスト、
チャンク、コンテナ全体のHashで破損を検出する。

## 作成トランザクション

1. 保存先がローカルNTFS／exFATで、対象・コピー元との分離条件を満たすか検査する。
2. 同じフォルダーへ所有する新規`.partial`を作成する。
3. 不変Source sessionからチャンクを読み、書込み直後のHash／認証を確認する。
4. 完成メタデータを確定し、選択された高速／完全検証を行う。
5. Windows VSS時は`BackupComplete`とSnapshot cleanupまで待つ。
6. 既存完成ファイルを先に失わない回復可能な入替えで完成名へ確定する。

高速検証でも即時読戻し、Hash／認証、最終メタデータ検査を省略しない。省くのは
完成後の追加全走査だけで、既定は完全検証である。

救出作成では、故障Sourceをコンテナ作成のために再読込しない。有限再試行を1回だけ
所有一時領域へ実行し、全書込み読戻しとflush後に同じ一時領域を再識別して読取り専用へ
封印する。`RescueRawCopyReport`の全量、欠損合計、LBA、試行、結果分類を再検証し、
欠損が選択payload外またはパーティション境界を横断する場合は黙って除外せず停止する。
封印済み一時領域から完成`.tsumugi.partial`を完全検証し、その一時領域を破棄できた後だけ
完成名へ確定する。一時領域の破棄失敗時は完成名を公開しない。破棄後にも保存先disk、
親Directory ID、既存完成ファイルIDを再識別し、画像`.partial`を通常ファイルとして識別して
完全検証済み長さと一致することを確認する。条件が変化していれば完成名を公開しない。

Windows所有一時領域Adapterは、正規化した完成パスへ`.rescue-stage.partial`を付けた隣接名だけを
`CREATE_NEW`で作る。NTFS／exFAT、単一物理disk extent、Sourceとの物理分離、一時領域と
最大画像寸法を合わせた空き容量、全親の非reparse、SYSTEM／Administrators／OwnerだけのDACL、
単一linkの通常ファイル、File ID・長さ・割当量を拘束する。書込み共有と削除共有を許さず、
封印時は書込みハンドルを閉じて`GENERIC_READ`で再openし、読取り専用状態のFile ID、時刻、
長さ、割当量、link数を二重観測する。cleanupはパス削除ではなく、同じ所有File IDのhandleへ
削除予定を設定する。WinPE製品入口では、この経路を実媒体検証が済むまで512バイト論理
セクターに限定する。

## 復元トランザクション

1. 書込み／削除共有なしの同一ファイルハンドルで全体を完全検証する。
2. 復元計画と対象要約を表示し、大文字`OK`を要求する。
3. 対象の安定識別、接続session、Geometry、容量を再検証する。
4. 対象レイアウトを退避して未完了状態にする。
5. bounded blockを書き、flushし、同じ対象ハンドルから即時読戻しする。
6. 全データとメタデータの検証後、GPT／MBRの完成を示す先頭側を最後にcommitする。

ディスク全体復元と個別パーティション復元を計画できる。個別復元先は既存区画
または未割当領域とする。稼働中Windows自身のシステムディスク復元は拒否し、PEで
イメージと対象を改めて選択する。

既存区画への個別復元は、上記4と6の区画表更新を行わない別経路である。確認済みの
source indexと、復元先の区画順・番号・offset・sizeを不変値として束縛し、選択区画の
範囲だけへ書込み、flush・即時読戻しを行う。書込み開始前と完了時に区画表全体が
レビュー時と同一であることを再検証し、他区画と区画表を変更しない。自動バックアップは
作成しないため、選択区画の既存データは回復不能になる。

未割当領域への配置は、イメージと同じGPT／MBR形式、空きentry、既存区画と重ならない
1MiB整列範囲、元区画と同じ容量を要求する。対象をoffline化して同じハンドルから現在の
区画表とrollback bytesを取得し、payloadを全てflush・読戻した後だけ新規1entryを公開する。
GPTはbackup entries/header、primary entries/headerの順、rollbackはprimary側から元bytesへ
戻す。protective MBR、Disk GUID、既存partition GUID／entryは変更しない。MBRはbootstrap、
disk signature、既存primary entryを保持し、最初の空きentryを1sectorで確定する。metadata
書込みまたは最終parseに失敗した場合は元bytesへrollbackして読戻す。自動バックアップは
作成せず、失敗時にもpayload bytes自体は未参照の未割当範囲へ残る場合がある。

対象外のUSBメモリ、起動中レスキュー媒体、Dynamic Disk、Storage Spaces、
WindowsソフトウェアRAID、不明なRAIDは書込み前に拒否する。USB筐体は同一接続中の
複合識別に限定し、切断後は再選択と`OK`を要求する。

## 現在の検証範囲

共通形式層では、暗号、形式、ストリーム、マニフェスト、イメージサービス、
復元トランザクションの単体試験を持つ。混在Source、破損、範囲外、対象差替え、
読戻し不一致、commit失敗などを合成I/Oで拒否する。

Windows／PEの通常（exact）復元では、ディスク全体と既存区画／未割当への個別復元を
製品UI、物理Target session、同一ハンドルEngineへ接続している。完全検証後の対象再識別、
オフライン化、範囲限定書込み、flush・読戻し、完了時レイアウト再検証を合成I/Oで
確認済みである。保持型GPTのbackup先行公開と各metadataの元bytes rollback、MBRの
書込み後故障rollbackも合成試験済みである。Windows API Adapterを持つが、今回の確認では
物理媒体へ書き込んでおらず、VM／実機受入は未実施である。

WinPE救出イメージ作成は、画面の明示選択からコピー元read-only化、保存先検証、所有一時領域、
有限救出、封印済み一時領域だけを読む単一`.tsumugi`作成、完全検証、一時領域破棄、保存先再識別、
完成名確定、救出専用結果表示まで接続した。SourceのMBRを救出後に変化させる合成試験でも、
コンテナ作成時に故障Sourceを再読込しないことを確認している。

Windows版は、既にread-onlyまたはofflineの非system・非removable GPT／MBRデータディスクだけを
512バイト論理セクターで受け付ける。Source属性を変更せず、開始時と読取り専用open後に安定識別、
sector構成、保護状態、レビュー済みpartition layoutを再確認する。同じ所有一時領域と共通サービスを
通し、画面でも欠損ゼロを含め常に救出専用結果として表示する。合成Sourceを救出開始後に変化させる
試験で、封印後のコンテナ作成がSourceを再読込しないことを確認した。実画面／VM／実媒体受入は未実施である。

残件は次のとおり。

- Windows実VSS WIM captureのVM／実機受入
- PE read-only Source Provider
- Windows／PE救出イメージの実画面・VM／実媒体受入と、4Kn条件付き経路
- exFAT／FAT32縮小captureと512系↔4Kn移行
- 高速／完全選択、暗号化、弱いパスワード警告を含む製品UI
- Golden file、後方互換、Fuzz、不正イメージ、故障注入、VM回帰

## 旧形式

旧イメージ形式は移行前の安全部品と試験証跡を理解するためだけに保持する。
正式版UI／CLIから開かず、公開変換機能を提供しない。旧形式の履歴文書は
現行仕様ではない旨を明記して保持する。
